# Styling [Tokens, the selector contract, and theming]

The shipped stylesheet dresses the footnote anatomy — superscript cues, the
short separator rule, the numbered notes list, the `↩` backrefs — and nothing
else. It is host-agnostic: it inherits your typography and colors, sizes in
`em`, and works on any light or dark background with zero configuration.

## The stylesheet

```ts
import 'lexical-footnote/styles.css';
```

That is the whole setup. Everything below is optional: a few tokens to re-skin
it, or the selector contract if you'd rather style it yourself.

## Theme tokens

Set any of these custom properties to re-color the anatomy; each has a fallback
that already works unthemed.

| Token                                | What it colors                                   | Falls back to             |
| ------------------------------------ | ------------------------------------------------ | ------------------------- |
| `--lexical-footnote-accent`          | cue numbers, list markers, backrefs, focus fills | `currentColor`            |
| `--lexical-footnote-accent-contrast` | text on the solid focus/selected fill            | the `Canvas` system color |
| `--lexical-footnote-note-color`      | the notes section's text                         | a softened `currentColor` |
| `--lexical-footnote-rule-color`      | the separator rule above the notes               | a faint `currentColor`    |

## Skipping the stylesheet

Nothing in the runtime depends on the stylesheet, so you can drop it entirely
and target the stable class names and data-attributes yourself. What the markup
exposes:

| Part            | Data-attribute                                 | Class                              |
| --------------- | ---------------------------------------------- | ---------------------------------- |
| notes section   | `[data-lexical-footnote-section]`              | `.lexical-footnote__section`       |
| notes list      | `[data-lexical-footnote-list]` (`<ol>`)        | —                                  |
| one note's item | `[data-lexical-footnote-item="<id>"]` (`<li>`) | `.lexical-footnote__item`          |
| definition body | —                                              | `.lexical-footnote__definition`    |
| cue             | `[data-lexical-footnote-ref="<id>"]`           | `.lexical-footnote__ref`           |
| selected cue    | —                                              | `.lexical-footnote__ref--selected` |
| backref         | —                                              | `.lexical-footnote__backref`       |

The backref buttons live in an overlay outside the editable content
(`.lexical-footnote__backref-overlay`, with one run per note in
`.lexical-footnote__backrefs`), absolutely positioned at the end of each note's
last line.

:::note
The `<li>` order in the DOM is slot-map order, not display order — the extension
projects visual position through the item's `order` and the marker number
through its `value`. Style off the list and its markers, not DOM adjacency.
:::

Tokens inherit, so set them on `:root` or on any ancestor — here a
`.fn-themed` wrapper — per color scheme, and the whole anatomy follows:

```css
// [!include ~/examples/footnoteTheme.css]
```
